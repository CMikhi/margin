# Frontend Design Review

## Goal

Evaluate the frontend as a professional UI/UX designer. Review only; do not modify code unless explicitly requested.

## Process

1. Inspect the project's existing design system and relevant interface components.
2. Identify brand guidelines, typography, colors, spacing, and reusable components. Distinguish established conventions from isolated inconsistencies.
3. Run the application if possible, using its existing setup and commands.
4. Capture and inspect desktop and mobile screenshots if browser tools are available. Check relevant interactions and states, including keyboard navigation where practical.
5. Evaluate:
   - Visual hierarchy
   - Typography
   - Spacing and alignment
   - Brand consistency
   - Responsiveness
   - Accessibility
   - Component consistency
6. Identify specific design weaknesses, citing the affected page, component, or file. Explain the effect on the user and recommend a concrete improvement.
7. Order recommendations by impact. Separate observed issues from assumptions, and report any views or interactions that could not be verified. Do not claim accessibility conformance from screenshots alone.

## Design Principles

- Preserve the established brand identity.
- Avoid generic, repetitive AI-generated layouts.
- Favor intentional visual composition.
- Do not introduce unnecessary components.
- Do not change the design system without justification.

## Output

Provide:

1. Overall assessment
2. High-priority issues
3. Specific recommended improvements
4. Accessibility and responsive issues
5. Areas requiring human design judgment

Keep recommendations proportional to the requested review scope. Avoid repeating the same finding across sections.
